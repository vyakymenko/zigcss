## Decisions

- The approved plan is authoritative.
- Security and semantic containment precede feature work.
- Inherited work is preserved and will not be rewritten or discarded.
- The compile API will be disabled after `SEC-001` unless `SEC-002` isolation is implemented and verified immediately.
- Legacy compiler failures are executable characterization quarantines, not accepted contracts. Each owning fix must replace its quarantine with the correct behavior assertion in the same commit.
- Legacy optimizer functions remain reachable only to explicitly labeled internal tests. They are not part of the stable CLI/code-generation path and must not be re-enabled without pass-specific acceptance evidence.
- Operator-requested post-Milestone-0 tooling: add a ZigCSS autonomous-loop protocol plus a read-only `orient.sh`, modeled on Alvo's protocol/orient split and adapted to this repository's no-push/no-deploy authority boundary.
- Alternate-format parsers remain available only as experimental internals for characterization; `.scss`, `.sass`, `.less`, `.styl`, `.postcss`, `.module.css`, and CSS-in-JS extensions are rejected by the recovery CLI before any output is written.
- The persistent Codex goal remains the scheduler. `scripts/autodevelop/orient.sh` is deliberately read-only and cannot launch a model, wake a task, or mutate repository/external state; `docs/operations/codex-loop-protocol.md` is the canonical resume procedure.
- Foundational implementation must conform to accepted `ADR-001`, `ADR-002`, `ADR-003`, `ADR-004`, and `ADR-010`; changing stable scope, source/syntax boundaries, ownership, transform authority, or autonomous runtime requires a superseding approved ADR.
- CSS strings use their distinct trailing-backslash-at-EOF rule when producing decoded values; identifiers, dimensions, hashes, at-keywords, and URLs retain the general escaped-code-point replacement behavior.
- The arena control block is separately allocated from its caller-provided backing allocator so allocators retained by movable child containers never point into a relocated `Compilation` value.
- Component-value recursion defaults to a 256-container nesting budget and returns `NestingLimitExceeded` before exceeding it; resource-limit diagnostics are added by `DIAG-001` rather than conflated with allocation failures.
- The allocation-free tokenizer records bounded recovery metadata on tokens; the compilation-backed syntax layer converts it to owned diagnostics so no allocation error can be swallowed inside `Tokenizer.next`.
- The new `src/css/ast.zig` model coexists with the inherited `src/ast.zig` prototype until Milestone 2 parsing/emission migration; stable recovery paths do not consume the legacy selector representation.
- Declaration lists are ordered slices rather than property maps, preserving fallback declarations and leaving cascade/importance decisions to later explicit passes.
- Rule lists remain ordered and recursive through pointers, preventing non-adjacent at-rules/rules from being merged by the data model itself.
- Column combinators remain representable in the AST but are not accepted by the stable parser because the current Selectors Level 4 grammar lists only descendant, child, next-sibling, and subsequent-sibling combinators. Native nesting accepts explicit `&`, leading combinators, and implicit parent references; a recursively encountered ampersand delimiter suppresses implicit-parent insertion metadata.
- Parsed declarations retain the complete raw value (including importance trivia/marker) while `valueWithoutImportance()` exposes the semantic prefix; no property map or early value interpretation may remove fallback order.
- Generic rule-list at-rules (`media`, `supports`, `container`, `layer`, `scope`, and related forms) recurse immediately; keyframes retain raw frame syntax for PAR-004, and page/unknown mixed grammars stay raw until their dedicated classifier can preserve all nested forms.
- Structured at-rule specialization keeps generic blocks as the recovery boundary. Keyframes retain the full raw frame stream alongside typed valid frames; page remains a raw mixed-content block alongside ordered typed declarations/margin boxes; malformed typed preludes never erase the underlying rule.
- Rule recovery uses the shared `css/recovery.zig` boundary contract: semicolon and complete curly-block boundaries always advance one component, EOF is stable, nested components remain opaque, and syntax diagnostics remain the sole report for stray closing tokens.
- Pretty emission follows CSSOM identifier/string escaping and CSS Syntax round-trip constraints. Comments inside raw component values are retained as token separators; generic structural whitespace is canonicalized; incomplete or partially lowered constructs are rejected before a successful output is returned.
- Pretty and minified emission are modes of the same implementation. Minified mode defaults to no final newline, may omit only a declaration immediately before its closing brace, and retains a semicolon when a following page item still needs an explicit declaration boundary.
- Unknown at-rule preludes and raw blocks preserve adjacency and edge whitespace-token presence in both emission modes. Pretty formatting may not insert a cosmetic separator into untyped syntax, and minification may collapse raw whitespace width but not erase the token.
- CSS source-map columns are zero-based UTF-16 code-unit offsets per ECMA-426. The map JSON includes `version: 3`, one ordered source, optional `sourcesContent`/generated file, no names, and strict four-field mappings; generated output and source-map ownership remain separate.
- Style blocks partition their source span between leading declarations and ordered child rules. Invalid block-bearing child rules still split declaration runs as CSS Syntax requires; their source gap remains explicit so both emitter modes reject recovered output rather than silently deleting authored bytes.
- Known declaration/keyframe/page/top-level-only at-rules are invalid in a nesting context and recover at their complete at-rule boundary. Raw unknown at-rules remain represented for forward compatibility; newly standardized forms require an explicit classifier/context decision.
- Stable parse diagnostics are emitted only after the complete typed parse and successful compilation produces no partial CSS. Parallel batch compilation likewise writes no destination until every task has compiled successfully.
- Independent grammar validation is pinned to exact Lightning CSS package bytes through `package-lock.json`. An upgrade changes the evidence baseline and must update the declared version and rerun both output modes for every fixture.
- Transform safety classes are independent permissions, not an ordinal hierarchy. Policy defaults to verified analysis only; transitive dependencies need the same explicit authority as requested passes. Stable `--optimize` is now confined to the static seven-definition preset whose complete membership has passed the acceptance suite.
- Transform deletions are proof-carrying AST entries, not trusted source spans. The emitter independently validates that an omitted rule is structurally empty and belongs to the closed cleanup set before skipping it; recursive omission proofs retain nested source coverage and surviving source maps never point into deleted rules.
- `zigcss-transform-test-driver` is installed only by `zig build test` for independent pass validation and does not enter the normal install artifact. Its individual compatibility/extraction routes remain test-only; its `verified-optimizer` route mirrors the stable CLI preset for independent differential validation.
- Duplicate analysis uses deterministic first-occurrence output order and bounded hash-backed counting, but copies report names and spans into caller-owned storage so results can safely outlive compilation. Default group, occurrence, property-byte, and recursion limits prevent report construction from becoming an unbounded resource sink.
- Numeric grammar and unit behavior are frozen by fixtures against the reviewed CSS Values and Units Level 4 and CSS Conditional Rules Level 5 drafts; dimension/percentage algebra follows CSS Typed OM Level 1. Living-spec changes require an intentional fixture and decision update rather than silently changing an optimizer result.
- `VAL-001` stores postfix typing evidence only. Context-dependent conversion, finite-value handling, precision policy, folding, and shortening remain `MATH-001` or later semantic-rewrite responsibilities and default to no rewrite when evidence is incomplete.
- Generated nodes use the smallest complete authored construct as their causal source span. Emission adds one mapping at the generated segment start and never invents inner mappings, borrows an adjacent span, or defaults to source offset zero.
- `MATH-001` folds only complete supported math-function values under an exact property category/range policy. Identical-unit finite arithmetic is eligible; cross-unit conversion, comments, substitutions, descriptors, unsupported properties, invalid ranges, ambiguous signed zero, and non-shorter output retain the exact input root.
- `OPT-012` treats compatibility as part of equivalence: opaque basic named/hex/RGB forms share the oldest closed output surface, while non-opaque functional/keyword colors remain authored unless alpha-hex support was already required. Unitless-zero shortening excludes percentage/dimension categories and every number-or-length ambiguity.
- `OPT-013` treats shorthand expansion as a reset-and-cascade proof, not a textual compression. Only an adjacent top/right/bottom/left group with identical importance and raw value spelling may become one `margin` declaration; logical properties, fallbacks, layers, media queries, and nested segments remain on the same side of the replacement boundary. Page and page-margin descriptor contexts are excluded until an independent computed/canonical oracle can verify them.
- `PREFIX-002` treats compatibility syntax as structured proof output. Complete unannotated forms may be added in deterministic target order, but the standard form remains last and no qualifier, unsupported gap, author-supplied vendor policy, or untyped selector context is interpreted into authority. Stable CLI exposure is a separate public API decision, not an automatic consequence of pass verification.
- `TREE-001` treats selector extraction as a closed-snapshot proof. Null inventory categories never mean empty, critical input must include the full selector-matching render tree, ASCII case variants conservatively retain rules, and one possible selector alternative preserves the entire style rule. The two modes remain experimental despite full package evidence and require two independent policy grants.
- Milestone 3 stable optimization is a closed preset, not a maturity wildcard. Because proof-carrying AST nodes deliberately block overlapping rewrites inside one source snapshot, the CLI reaches a bounded emitted-byte fixed point through validated reparses. Source maps are not exposed across those intermediate snapshots until a composed-map proof exists.
- `API-001` reuses the ownership-safe library root established by `ARCH-001` instead of creating a parallel facade. External-consumer compilation is the export gate; a symbol used only through implementation-relative imports does not count as public. The existing low-level modules remain experimental until `API-002` defines the stable compile facade.
- `API-002` keeps target queries caller-owned and borrowed only for the duration of `compile`; no target-query pointer enters a result. Dependencies are facts, not fetch instructions: only decoded top-level string/URL `@import` operands are reported, authored order and duplicates remain observable, unsupported preludes are not guessed, and resource-limit failure discards partial facts. Fixed-point optimization remains incompatible with source maps until intermediate mappings can be composed. Stable CSS deliberately returns `module_exports = null` pending `MODULE-001`.
- `API-003` confines native plugins to `plugin.` IDs and borrowed synchronous lifetimes. The closed optimizer finishes before the plugin plan; target prefixing participates in that final plan under global phase/priority/ID order. Plugin-only policy validation happens before compatibility authority is added for the built-in prefix pass, so no plugin can gain a class transitively. Active plugin source maps remain unavailable, `API0002` identifies invalid configuration, `API0003` identifies transactional execution failure, and native panic/UB/nontermination requires consumer process isolation rather than a false in-process recovery promise.
- `BUILD-001` assigns package identity fingerprint `0xae272a4871e93d07`; changing it would change package identity and requires an explicit ownership decision, not version maintenance. Version 0.3.0 matches the current npm manifest, and `minimum_zig_version = "0.15.2"` names the earliest tested baseline while CI remains pinned to that exact toolchain. The initial `.paths` list deliberately excludes `build_helpers.zig` until `BUILD-002`, and no remote URL/hash is documented before a published artifact exists.
- `BUILD-002` treats CSS compilation as a normal `Step.Run` assembled before execution: `LazyPath` input, generated output argument, tool dependency, bounded stdio, and exact downstream check. Multiple files require multiple independent helper calls, which preserves per-file cache keys and declared outputs. Portable output basenames prevent caller-selected paths from escaping the build cache. The artifact is a host tool; application cross targets must not be executed as build tools. Unsupported CLI features are absent rather than represented as accepted no-ops.
- `BUILD-003` treats examples as executable consumer contracts, not illustrative snippets. The build project obtains a separate host dependency for the compiler tool and a target dependency for application imports; CI compiles both supported safe modes, while a repository enumeration test fails when an authored Zig example has no declared build path. Generated caches and install outputs are never considered authored examples.
- `CLI-010` defines the executable/library boundary at `zigcss.compile`: option selection and owned-result consumption belong to the CLI, while parsing, transforms, dependencies, and emission stay in the library. The separately experimental LSP route retains its explicitly documented legacy boundary until Milestone 6. Because the public facade has no truthful internal timing hooks, `--profile` reports one end-to-end compile duration instead of inventing stage precision; `PROF-010` owns accurate stage and allocator metrics.
- `CLI-011` reserves `-` exclusively as the standard stream sentinel. Stdin is bounded by the same 10 MiB CLI input limit, receives the stable diagnostic name `<stdin>`, and is deliberately single-shot rather than watch/batch input. Only CSS syntax is accepted; future syntax tags require their owning format packages. Exit 0 means success/info, 1 means compilation or operational I/O failure, and 2 means caller usage/configuration failure. Informational/CSS bytes use stdout while warnings/errors use stderr. A POSIX signal remains a signal through the npm launcher rather than being flattened into an invented numeric success.
- `CLI-012` defines atomicity at one destination, using a temporary sibling and rename rather than in-place truncation. Parent creation is deliberately delayed until a successful result is committed, but a batch does not promise rollback of earlier independently committed files after a later operational failure. Existing destination link entries are replaced rather than followed. Batch names derive only from the final stem and, when needed, a normalized relative-path hash; order never participates, basename length is bounded, and the final path-identity gate remains the collision authority.
- `WATCH-001` treats the root's already-read bytes as the one compile snapshot and records that snapshot before attempting compilation. Error state is a watch state rather than a retry request. Direct dependency facts are watched conservatively only when they are local relative filesystem paths; URL schemes and absolute/origin-relative forms are not reinterpreted into local access, queries/fragments are not path bytes, imports are not recursively parsed or inlined, and failed roots retain the last valid direct set. Path deduplication follows the same platform case policy as output planning, while content and read-error transitions remain deterministic.
