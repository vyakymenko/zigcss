# ZigCSS 0.6 stable release status

ZigCSS 0.6.0 is the published stable release: all five machine rows are native-graduated, and the immutable non-prerelease GitHub Release, 25 signed assets, npm `latest` package with SLSA provenance, preserved `next`, and anonymous five-syntax install are verified. Immutable 0.6.0-rc.2 remains the published native prerelease on npm `next`; stable publication does not rewrite it.

## Current boundaries

The source-built binary accepts the closed `--syntax <css|scss|sass|less|stylus>` set. CSS routes through the stable native `zigcss.compile` facade. SCSS, indented Sass, Less, and Stylus route through self-contained native Zig parser/evaluators, then complete generated CSS enters the same recovery-disabled core. The package JavaScript wrapper only locates and invokes that binary; it hosts no language semantics and this snapshot claims no programmatic JavaScript preprocessor API. A native frontend or generated-CSS failure returns no partial result.

Single-file, watch, and mixed batch compilation retain explicit file/stdin and file/stdout modes. Watch compiles one owned root snapshot and tracks native confined dependencies. Batch mode uses at most eight workers; the first failure closes the queue and only complete success reaches argument-ordered atomic writes. `--version` stays synchronized to package metadata, every option is non-repeatable, and exit statuses distinguish success/info (`0`), compilation/I/O failure (`1`), and usage/configuration failure (`2`). Deterministic output names disambiguate colliding stems with normalized-path hashes and cap basenames at 128 bytes. Each destination is atomic, while a multi-file batch is not claimed as one filesystem transaction. The typed CSS boundary is listed in the [CSS compatibility matrix](/guide/css-compatibility); native frontend boundaries are listed in [format compatibility](/guide/format-compatibility).

The experimental LSP transport owns each request body independently, accepts sequential HTTP-style header blocks terminated by exact CRLF pairs, and exits cleanly at a frame boundary on EOF. Headers are bounded to 8 KiB and each dynamically allocated body to 16 MiB. Missing, duplicate, non-decimal, overflowing, oversized, malformed, or truncated `Content-Length` framing is rejected before JSON handling. A real child-process transcript covers a request above the former 8 KiB ceiling followed by a second request.

Each framed body is parsed by the standard Zig JSON parser and every reply is emitted through `std.json.Stringify`; string IDs, dynamic URI keys, replacement text, diagnostic messages, and hover Markdown are escaped rather than interpolated. String, number, null, and arbitrary-precision numeric IDs retain their JSON type. Malformed JSON returns `-32700`, an invalid request envelope returns `-32600`, an unknown method returns `-32601`, and invalid method parameters return `-32602`. A malformed framed request does not terminate the server, and the next frame is processed normally.

The server now follows the LSP 3.17 initialize/shutdown/exit lifecycle. Valid notifications never produce response frames; pre-initialize notifications are dropped, pre-initialize requests return `-32002`, and `initialize` succeeds only once. The advertised `textDocumentSync` capability is exactly `{ openClose: true, change: 1 }`; open requires complete client-owned text, changes require one full replacement at a strictly increasing 32-bit version, duplicate/stale/incremental/unopened notifications do not mutate state, and close releases the owned URI/text. `$/cancelRequest` IDs are validated and the notification is safely ignored because this server deliberately finishes each request synchronously before reading the next frame, so no request can be in flight when cancellation is read. `shutdown` returns `null` without exiting, subsequent requests return `-32600`, and `exit` terminates with status 0 only after shutdown or status 1 otherwise.

Initialization explicitly advertises `positionEncoding: utf-16`, the LSP 3.17 default and mandatory encoding. One shared converter maps request positions to UTF-8 byte offsets and compiler byte spans back to zero-based UTF-16 code-unit ranges. It recognizes LF, CRLF, and lone CR without permitting a position inside CRLF, counts astral scalars as two units, clamps an overlong character to the line end, and rejects negative, overflowing, invalid UTF-8, or mid-surrogate positions as invalid parameters. Unit tests cover both conversion directions and malformed boundaries; an executable transcript proves that an astral prefix and CRLF still return the exact UTF-16 definition range.

The server advertises `diagnosticProvider` with identifier `zigcss`, no inter-file dependencies, and no workspace diagnostics. The standard singular `textDocument/diagnostic` request compiles the currently synchronized CSS bytes through the same external `zigcss.compile` facade as the CLI and returns a `kind: full` report. Each owned compiler diagnostic preserves authored order, exact message, `CSS`/`API` code, mapped severity, and a span-derived UTF-16 range; recoverable input can therefore return multiple useful problems rather than the inherited parser's first error. Valid CSS returns an empty full report. The optional matching identifier and string `previousResultId` are validated, but no result ID is issued and every response remains full until a cache has measured value. The prototype plural method is rejected with `-32601`, unopened documents or malformed provider parameters return `-32602`, and operational compiler failures return `-32803`. Removed, library-only, and unknown formats never fall back to CSS: they receive one `CSS0009` diagnostic.

Initialization now advertises hover, completion, document symbols, workspace symbols, definition, references, and rename. Every feature lazily builds a bounded per-version index from the rebuilt typed CSS pipeline; a successful full change invalidates the old index and close frees it. Cross-document operations inspect only currently open CSS documents, sort by URI and then source order, and never scan the filesystem, load imports, or infer an unopened project graph. Persistent state defaults to at most 4,096 documents, 256 MiB of synchronized text, 16 MiB of aggregate URI bytes, 64 KiB per URI, and 128 MiB of allocator-measured cached index storage. Workspace requests admit at most a 256-byte query and 100,000 results; every editor response is conservatively preflighted against a 16 MiB escaped-JSON budget before serialization. Each index independently caps symbols, properties, declaration contexts, opaque spans, individual decoded names, total owned name bytes, allocation bytes, and completion scan work. Opens and changes cross-check their replacement totals before allocation or mutation, so a rejected update retains the previous version and index state; an index that would exceed its 32 MiB document or aggregate workspace budget is destroyed before a request-failed response.

The index recognizes typed class and ID selectors (including parsed selector-list pseudo arguments), custom-property declarations and `@property` definitions, `var()` references, keyframe definitions, and unambiguous `animation-name` references. String, comment, and URL contents are opaque except for grammar-defined quoted keyframe names; ambiguous animation shorthands and invalid recovered animation-name lists are not guessed. Class and ID selectors represent external DOM names, so they support hover, symbols, references, and syntax-only rename but deliberately return no stylesheet definition. Custom properties and keyframes support open-document definition/reference/rename. Completion offers only a closed property-name list in declaration-name contexts and returns an exact UTF-16 `textEdit`; values, selectors, strings, and comments receive no speculative items. Rename validates the symbol kind, rejects NUL or malformed UTF-8 names, and emits safely serialized CSS identifier spelling. Distributable editor packaging remains owned by the editor packages.

The final protocol stress transcript starts with malformed JSON and an invalid request envelope, then initializes the real executable, synchronizes more than 1 MiB of CSS, and proves exact Unicode custom-property definition and property-hover ranges across an astral prefix, CRLF, and non-ASCII identifiers. The same document returns a compiler-backed empty diagnostic report, close makes the next positional request invalid, shutdown returns null, exit succeeds, notifications stay silent, every response frame is consumed exactly, and response output remains below 64 KiB. A separate allocator-checked test repeats Unicode open/index/full-change/re-index/close ownership 64 times and requires document, text, URI, and allocator-measured index state to return to zero after every cycle. Together with exhaustive frame, JSON, state, and editor allocation-failure tests, this completes `LSP-007`.

The experimental VS Code workspace extension maps core 0.6.0-rc.2 to Marketplace version 0.6.0 because VS Marketplace accepts only `major.minor.patch`; the verified `--pre-release` package marker preserves the channel. It installs reproducibly from its exact npm lockfile, activates only for file-backed CSS, contributes no competing preprocessor languages, launches no unused filesystem watcher, and is disabled in untrusted and virtual workspaces. An empty server-path setting checks a future extension-local `bin` directory and then only absolute `PATH` entries; an explicit setting must be a verified absolute executable or a bare command resolved through those entries. Relative paths never execute from the current workspace, POSIX candidates require executable permission, and Windows lookup uses `Path` plus `PATHEXT`. Thirteen cross-platform discovery, real-file, manifest, version, and workflow tests pass. Pinned TypeScript and esbuild produce one CommonJS runtime; pinned official `vsce` 3.9.2 admits exactly `package.json`, README, project license, third-party dependency notices, and `dist/extension.js`, then creates a temporary pre-release VSIX whose ZIP signature and bounded size are checked before cleanup. CI uses Node 22, `npm ci --ignore-scripts`, tests, and the package check. No native binary enters the VSIX, no registry/marketplace action is performed, and publication remains unauthorized.

The runtime file attaches only to CSS, supports a `.git` workspace root or a single file, and sets the completion omnifunc only after the real client advertises completion. `ZIGCSS_LSP_PATH` must name an absolute regular executable; otherwise at most 1,024 absolute `PATH` directories are searched (with bounded `PATHEXT` handling on Windows) before the exact `--lsp` argument is appended. The build registers `src/lib.zig` as the external `zigcss` module. A separate consumer test imports that name rather than testing from inside the root, then calls the owned high-level compile facade. Results retain CSS, optional map bytes, source names and line/column locations for diagnostics, ordered decoded top-level `@import` dependencies, optional module-export state, and optional profile metrics after compilation cleanup. ## Experimental native plugin boundary

Native plugins reuse the immutable pass contract; the inherited mutable `PluginRegistry` is not public. Definitions, metadata strings, request/dependency slices, callbacks, and `user_data` are borrowed only during synchronous `compile`, while all AST output stays in the compilation arena and no plugin pointer enters `CompileResult`. IDs must use the isolated `plugin.` namespace. Only requested IDs and their plugin dependencies execute, after the optional optimizer fixed point; a target prefix pass joins the same final plan. Dependencies take precedence, then ready passes are ordered by phase, ascending priority, and bytewise stable ID.

The outer `.experimental` tag does not grant transform authority by itself. `PluginPolicy` still defaults to verified analysis only; experimental maturity and each output-changing safety class require their own exact booleans. Invalid registries or policy return owned `API0002` diagnostics before callbacks or dependency collection. Callback/validator failure rolls back the compiler root and plan diagnostics, returns owned `API0003` without CSS, and retains already discovered import facts. Caller-owned `user_data` side effects are not reversible. Warnings survive only when the whole plan succeeds.

This is trusted in-process Zig code, not a sandbox or stable ABI. A panic, nontermination, process exit, undefined behavior, or malicious mutation cannot be recovered. Plugins remain unavailable from the recovery CLI and disabled public compiler routes. The complete source contract is recorded in `docs/adr/ADR-011-native-plugin-contract.md`.

Property-specific values are generally preserved as component trees rather than fully validated semantic values. Browser computed-style validation, broader target data and stable CLI prefix exposure, optimized source-map composition, CLI source-map output, filesystem-backed LSP workspace loading, editor publication/binary distribution, CSS Modules ID/keyframe scoping and external value/ICSS resolution, other alternate formats, and public untrusted compilation remain later gates. Independent syntax acceptance is evidence, not a complete browser-semantics guarantee.

## Verified optimizer boundary

`--optimize` invokes one static preset: duplicate-declaration analysis, empty-rule cleanup, numeric math folding, typed color/zero shortening, margin shorthand synthesis, adjacent at-rule merge, and adjacent selector-rule merge. Every definition is verified, validator-backed, recursively nested, order-preserving, and independently acceptance-tested. The preset policy grants only cleanup and semantic rewrite; target compatibility, extraction, experimental passes, reorder authority, custom-property resolution, and logical-to-physical conversion have no path into it.

Because one proof-carrying rewrite can expose another safe candidate after emission, the preset runs bounded parse-transform-emit rounds until two consecutive byte sequences match. The 32-round limit fails without partial output. Its combined pretty/minified fixture covers cross-pass candidates, fallback and importance order, custom/logical preservation, nested groups, unsupported values, exact byte idempotence, independent Lightning CSS canonical semantics, and size reduction. Fixed-point source-map composition is not yet exposed; the CLI continues to reject `--source-map`.

## Experimental extraction boundary

The library exposes distinct conservative dead-code and critical-CSS passes. A non-null class or ID category is exhaustive for the declared domain; null is unknown and cannot prove absence. Dead-code mode requires a closed document snapshot. Critical mode requires a closed selector-matching render tree that includes every related node a combinator can inspect—not merely a list of preferred names from a larger live page.

Only direct positive class and ID requirements participate. A style rule is removed only when every selector-list alternative contains a required token absent from a complete category. Type/attribute evidence, functional pseudo arguments, possible selector alternatives, imports, descriptors, keyframes, custom-property dependencies, layers, and other non-style rules remain authored. Inventories are owned, canonical, bounded, and conservative across ASCII case variants.

Both modes remain experimental and library/test-driver only. They require `allow_extraction` and `allow_experimental`, pass independent Lightning CSS selector projection in pretty and minified modes, and are never reached by `--optimize` or `--critical-*`.

## Library target boundary

The experimental Zig API accepts comma-separated explicit minimums such as `chrome >= 120, firefox >= 115, safari >= 17.2`. The closed browser set is `chrome`, `edge`, `firefox`, `safari`, `ios_safari`, and `ie`. Queries are lowercase, contain no defaults, and do not implement Browserslist market-share, recency, negation, alias, or configuration syntax.

Compatibility facts are generated from the exact `@mdn/browser-compat-data` 8.0.0 lock for a reviewed eight-feature property/value/selector/at-rule subset. The verified library pass emits only complete, unannotated closed forms, keeps vendor declarations before the authored standard, separates vendor selector rules, clones prefixed keyframes, retains manual vendor policy, and produces deterministic source maps. A modern Chrome/Edge/Firefox query is an exact no-op; the reviewed legacy query materially changes output and passes independent Lightning CSS projection in both modes.

This is still not general autoprefixing. Partial, annotated, unsupported, mixed-selector, functional-pseudo, descriptor, recovered, and conflicting/manual cases default to no rewrite. `--browsers` and `--autoprefix` continue to fail until later public API/CLI work carries the target query and authorizes only the rebuilt pass.

Use stable 0.6.0 within the capability matrices and explicit plugin/execution boundaries above. Evaluate representative project stylesheets before production adoption; unsupported ecosystem hooks fail closed rather than silently falling back.

## Tooling integration boundary

The published npm package is a CLI launcher, not a JavaScript compile API or a collection of bundler adapters. Zig Build consumption and the installed CLI path are verified. The website's own Vite build and local development middleware do not prove that ZigCSS is a Vite stylesheet plugin. There is currently no official or end-to-end-tested Webpack loader, Rollup/Vite plugin, esbuild plugin, or Nx executor; Rspack, Turbopack, Parcel, Next.js, Nuxt, Astro, Angular, and SvelteKit are likewise unverified. Projects may call the CLI as an explicit prebuild step, but should not interpret that generic process boundary as native tool integration.

## Project direction

The completed recovery program replaced the stable CLI's byte-oriented parser with a tokenizer, source model, syntax tree, standards-oriented parser, and semantics-preserving emitter. It enables only the closed evidence-backed optimizer preset while separately gated or inherited transform paths remain unavailable. Public performance comparisons remain withdrawn because no controlled scheduled archive has been selected; BENCH-007 can render only a committed archive whose report, source/run provenance, hardware fingerprint, raw statistics, and artifact link all revalidate.
